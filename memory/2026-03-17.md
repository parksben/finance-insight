## PengAn 产品需求：群聊共享记忆（重要）

**需求描述：** 在牛马产品的项目群聊中，所有 Agent 应该自动沉淀和积累对话记忆。当用户某天打开一个群聊，里面的 Agent 不能"断片"。

- 群里的 Agent 应该共享项目上下文和历史决策
- 不能依赖单个 Agent 的 session 记忆（session 会过期/compaction）

**待实现方案（产品侧）：**
1. niuma-server 层面：每条消息持久化后，定期自动 summarize 聊天历史 → 写入 knowledge_docs
2. Agent 回复时，自动从 knowledge_docs 加载项目上下文（现有的 kbContext 机制可以扩展）
3. 可选：planner 角色定期做"项目记忆整理"，生成结构化摘要文档

## niuma-server sqlite3 原生模块 bug 修复（05:20~05:29）

### 根因
- `sqlite3` npm 包是 C++ 原生插件（.node），Bun `--compile` 无法打包
- 编译后的二进制运行报 `Could not find module root` → ENOENT

### 修复（commit fc7547c → 88b76ce, v0.1.3）
- `src/db.js` 自动检测运行时：`globalThis.Bun` 存在用 `bun:sqlite`，否则用 `sqlite3`
- 统一暴露 `runAsync/getAsync/allAsync` Promise API
- 新增 `safeAlter()` 替代所有 `db.run(ALTER..., () => {})` 回调
- `src/models/credential.js`: 改用 `runAsync`，不再接收 raw db 对象
- `src/services/WorkspaceService.js`: `migrate()` 改用 `runAsync` + `safeAlter`
- `index.js`: 删除 `sqlite3.verbose()` + raw db 创建，直接调 `initCredentialsSchema()`
- 清除所有代码中对 `db.run/db.get/db.all` 的直接调用
